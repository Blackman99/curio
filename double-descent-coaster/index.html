What is this?

The models. n training points, x spread over [−1, 1] by a golden-ratio sequence, with y = sin(3πx)·e−x² + 0.3x plus Gaussian noise of size σ. A model with width p is random-feature regression: p features cos(ωjx + bj)·√(2/p) with fixed random frequencies ωj (12 × a Cauchy draw, the random Fourier features of a Laplace kernel; Rahimi & Recht, 2007) and phases bj, and only the p output weights are fitted. Below p = n that is ordinary least squares; above it there are infinitely many exact fits and the page takes the one with the smallest ‖w‖, which is what gradient descent from zero finds. With ridge on, it minimises squared error + λ‖w‖².

The track. Every width from 1 to 64, then 24 widths per doubling up to 512, is fitted 11 times, each with its own draw of 512 features (a model with p features uses the first p). Test error is the mean squared distance from the true curve at 201 evenly spaced points; the track’s height is the median of the 11, on a log scale that is squeezed above 100 and below 0.003 (the tick marks show where). The on-ride photo shows all 11 fits faintly and the median one bright.

Why the spike. At p = n the model has exactly enough freedom to pass through every point, and only one way to do it; with noisy points that one way needs huge weights and swings wildly between them. Past the threshold the smallest-norm fit can spread the noise thinly over many features (Belkin, Hsu, Ma & Mandal, 2019). With the noise off there is no spike; a small ridge flattens it (Nakkiran et al., 2020); and near the threshold more data can hurt (Nakkiran, 2019).

How typical is this ride? Across 72 pairs of data and feature seeds (n = 24, σ = 0.15), the worst width after p = 1 is within one step of p = n in 52, the far end beats the best model with p < n in 68, and the median spike is 153× the valley. The default ride is one of them (data 9, features 2). In one dimension overfitting is never quite free: the far end still pays for the noise it passes through, just thinly.

Real and not. Every fit, error and weight norm is computed in your browser in float64 (Householder QR for least squares and minimum norm, Cholesky for ridge) and checked against LAPACK’s solver on the same inputs. Right at p = n the problem can be so ill-conditioned (condition numbers past 1014, mostly with n near 32) that float64 has no digits left; there both solvers agree only that the error is enormous. The data are synthetic, from a seeded random number generator. The coaster’s speed is a rough gravity model for show; only its height carries data.
