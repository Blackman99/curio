What is this?

Monte Carlo tree search chooses a move by playing thousands of quick random games. Each playout has four steps. Select: from the current position, keep stepping to the child with the highest UCB1 score, W/N + c·√(ln Nparent / N), which weighs moves that have won (W wins in N visits) against moves it has barely tried. Expand: at the first position with an untried move, add one at random to the tree. Simulate: play random moves to the end of the game. Back up: every node on the path gets one more visit, and a win if its mover won (half for a draw). When the budget is spent it plays the move with the most visits.

The bonsai is that tree, drawn as it is: every twig is one node. A branch's thickness is √visits, so its cross-section grows with the playouts through it. A node's visits are its children's visits plus the one playout that created it, so the tree obeys Leonardo da Vinci's rule for real trees: the branches' cross-sections add up to the trunk's. Leaf colour is how the playouts through that twig went for the side that searched. Blossoms are final positions where it wins; dark leaves are ones where you do.

When a move is played, every other branch is cut off and the chosen one becomes the new trunk, so the next search starts with the playouts already spent on that line (tree reuse). The knots on the trunk are those cuts.

Real: the game, the search and every number on screen, computed live in your browser. Its randomness is seeded (mulberry32), so a game replays exactly; a separate Python implementation reproduces its visit counts to the last playout. Artistic: the drawing: each column sends its branch in its own direction, and the curves, sway and leaves are decoration. When you watch, the search is slowed down so you can see it grow; at full speed it runs about 150,000 playouts a second here.

It is plain UCT with uniformly random playouts and no Connect Four knowledge, so with a small budget it misses wins and threats a beginner would see. In the tour's position, 30 playouts find the block at f for 66 of 200 random seeds, 128 playouts for 176, and 512 or more for all 200. Connect Four is solved: the first player wins by starting in the middle column (Allis 1988). On an empty board this search already prefers the middle from about 1,000 playouts.

After Kocsis & Szepesvári, Bandit Based Monte-Carlo Planning (ECML 2006); Coulom, Efficient Selectivity and Backup Operators in Monte-Carlo Tree Search (2006); Browne et al., A Survey of Monte Carlo Tree Search Methods (2012); Allis, A Knowledge-based Approach of Connect-Four (1988).
